Same API. Different user experience.

The server returns the same JSON in both UI modes. The slow mode adds client-side work after the API response, which protocol-level HTTP timing cannot observe.

Key finding: the chart compares browser timings only; the direct API p95 is shown separately above. Slowing the browser does not slow the API itself. The browser-observed median changed by 867.9 ms (7.5× as long). This is why a successful HTTP load test is not proof of good frontend responsiveness.

The browser and API figures are intentionally labeled separately because their durations cannot be treated as the same metric.

Playwright's click-to-visible time is an end-to-end automation observation. It is not a standardized paint measurement such as LCP or INP. Normal and slow modes use the same HTTP endpoint; the extra ~900 ms is created in browser JavaScript after the JSON has arrived. Small samples are adequate for this teaching demonstration, not for a production performance SLO.
